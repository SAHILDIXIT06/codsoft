- To Build a machine learning model to identify fraudulent credit card
transactions.
- To  Preprocess and normalize the transaction data, handle class
imbalance issues, and split the dataset into training and testing sets.
- To  Train a classification algorithm, such as logistic regression or random forests, to classify transactions as fraudulent or genuine.

# Credit Card Fraud Detection

Machine learning pipeline that detects fraudulent credit card transactions in a highly imbalanced dataset (0.17% fraud rate), comparing three class-imbalance strategies across two classification algorithms and evaluating with metrics suited to rare-event detection.   

## Problem

Given anonymized, PCA-transformed transaction data, classify each transaction as genuine or fraudulent. The core challenge isn't the algorithm — it's that fraud is extremely rare (492 out of 284,807 transactions), so a naive model that always predicts "genuine" would be 99.83% accurate while catching zero fraud.

## Dataset

[Credit Card Fraud Detection (Kaggle / ULB Machine Learning Group)](https://www.kaggle.com/mlg-ulb/creditcardfraud) — 284,807 transactions by European cardholders in September 2013. Features `V1`–`V28` are PCA components (original features withheld for confidentiality); `Time` and `Amount` are the only raw features. `Class` is the target (1 = fraud, 0 = genuine).

## Approach

1. **EDA** — quantify the class imbalance and inspect the `Amount`/`Time` distributions.
2. **Preprocessing** — standardize `Time` and `Amount` (the PCA components are already scaled); stratified 80/20 train/test split so the test set keeps the real-world fraud rate.
3. **Imbalance handling** (fit on the training set only, to avoid leakage into the test set):
   - Class weighting (`class_weight="balanced"`)
   - Random undersampling of the majority class
   - SMOTE synthetic oversampling of the minority class
4. **Models** — Logistic Regression and Random Forest, trained under each of the three strategies (6 combinations total).
5. **Evaluation** — precision, recall, F1, ROC-AUC, and **PR-AUC** (the primary ranking metric, since ROC-AUC is misleadingly optimistic under extreme imbalance).

## Results

| Model                                     | Precision       | Recall          | F1              | ROC-AUC | PR-AUC          |
| ----------------------------------------- | --------------- | --------------- | --------------- | ------- | --------------- |
| **Random Forest + class weighting** | **0.833** | **0.816** | **0.825** | 0.981   | **0.826** |
| Random Forest + SMOTE                     | 0.546           | 0.857           | 0.667           | 0.980   | 0.816           |
| Logistic Regression + SMOTE               | 0.058           | 0.918           | 0.109           | 0.970   | 0.725           |
| Logistic Regression + class weighting     | 0.061           | 0.918           | 0.114           | 0.972   | 0.719           |
| Random Forest + undersampling             | 0.044           | 0.918           | 0.085           | 0.977   | 0.696           |
| Logistic Regression + undersampling       | 0.038           | 0.918           | 0.074           | 0.976   | 0.678           |

**Best model: Random Forest with class weighting** — precision 0.83, recall 0.82, F1 0.82 on the held-out test set, catching 80 of 98 fraudulent transactions with only 16 false alarms out of 56,864 genuine ones.

**Key takeaway:** undersampling maximizes recall (~0.92 across the board) but destroys precision, because throwing away most genuine transactions makes the model trigger-happy — impractical in production, where each false alarm has a real cost. Class weighting kept all the training data and gave the Random Forest the best balance of catching fraud without flooding analysts with false positives.

## Possible extensions

- Try gradient-boosted trees (XGBoost / LightGBM) for comparison.
